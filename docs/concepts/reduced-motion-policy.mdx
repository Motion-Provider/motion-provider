Motion Provider respects the operating system's `prefers-reduced-motion` setting by default. When reduced motion is active, an animation skips playback and immediately applies its destination state.

## Choosing a policy

Every animated component accepts the `reducedMotion` prop:

| Value | Behavior |
| --- | --- |
| `user` | Follows the system preference. Default. |
| `always` | Always skips animation playback. |
| `never` | Always plays the animation, regardless of the system preference. |

```tsx
<MotionContainer
  animation={{ mode: "fadeUp" }}
  reducedMotion="user"
/>
```

The policy is available on `Motion`, `MotionContainer`, `MotionChain`, `MotionText`, and `MotionImage`. Keep `user` for ordinary interface motion. Use `never` sparingly: it deliberately overrides the user's accessibility preference.

<Callout type="warning" title="Do not use motion as the only feedback">
  Reduced motion can remove the transition entirely. Make sure state changes, progress, and interaction feedback remain clear without animation.
</Callout>

Use `useReducedMotion()` when your own client-side UI needs to read the current system preference. It returns a boolean and subscribes to preference changes; it does not override the policy of an animated component.
