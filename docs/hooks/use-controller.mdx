**Use `useController()` when animation playback should be driven by application events instead of only viewport visibility or a boolean trigger.** The hook creates one stable `AnimationController` for the lifetime of the mounted React component and lets every Motion Provider component that receives it register its animation with the same command store.

This is the API to reach for when a button, hover state, workflow step, route transition, or other interaction needs to **play, pause, reverse, seek, finish, reset, or cancel** one or several animations together.

<Callout type="note" title="useController is a client hook">
  The Motion Provider components themselves can render from a Server Component, but the component that calls `useController()` must be a Client Component because it uses React state internally.
</Callout>

## Signature

```tsx
const controller = useController(initial?);
```

The optional `initial` object seeds the controller with a command before any animations register.

| Option | Type | Default | Behavior |
| --- | --- | --- | --- |
| `stopAnimation` | `boolean` | `false` | Stores a `finish` command. Animations that register later settle immediately at their final state. |
| `reverseAnimation` | `boolean` | `false` | Stores a `reverse` command. Animations that register later begin in reverse playback. |

If both options are `true`, **`stopAnimation` takes precedence** because the hook applies it first.

The object is read *once when the hook instance mounts*. Updating the object later does not recreate or reconfigure the controller; call controller methods to change playback after mount.

<Callout type="warning" title="stopAnimation means finish, not pause">
  `stopAnimation: true` calls `finish()`. That moves registered animations to their destination state immediately. Use `pause()` when you need to freeze playback at the current timeline position.
</Callout>

## Return value

`useController()` returns an `AnimationController`. The same object instance is preserved across component re-renders.

### Playback commands

| Member | Return value | What it does |
| --- | --- | --- |
| `play()` | `Promise<AnimationResult[]>` | Plays every registered animation forward. |
| `reverse()` | `Promise<AnimationResult[]>` | Reverses the registered group from a shared timeline position. |
| `pause()` | `void` | Pauses every registered animation at its current position. |
| `finish()` | `void` | Finishes every animation immediately and applies its final state. |
| `reset()` | `void` | Returns animations to their initial state and leaves them paused. |
| `cancel()` | `void` | Cancels playback and restores the underlying DOM styles. |
| `seek(progress)` | `void` | Pauses the group and seeks to normalized progress. Values are clamped to `0...1`. |
| `setPlaybackRate(rate)` | `void` | Updates the playback rate of every registered animation. |

`play()` and `reverse()` resolve with one `AnimationResult` per registered animation. Calling either method before anything has registered is valid and resolves with an empty array; the controller still remembers the command for later registrations.

<Callout type="warning" title="seek has two important constraints">
  `seek()` accepts only finite numbers, and normalized seeking is not supported for animations with `iterations: Infinity`. Infinite animations raise an `INFINITE_SEEK` runtime error instead of inventing a finite progress range.
</Callout>

### Registration and compatibility members

| Member | Purpose |
| --- | --- |
| `size` | Number of animation handles currently registered with the controller. |
| `getSnapshot()` | Returns the latest command, or `undefined` before the first command. |
| `subscribe(listener)` | Subscribes to command changes. Motion Provider uses this for controller integration. |
| `register(handle)` | Registers a low-level `AnimationHandle` and returns its unregister function. Motion components call this for you. |
| `onReverse()` | Compatibility helper that toggles between `reverse()` and `play()`. |
| `onStop()` | Compatibility alias for `finish()`. |
| `control` | Returns the controller itself for compatibility with older controller-shaped APIs. |

Application code normally uses the playback methods and lets `MotionContainer`, `MotionChain`, `MotionText`, `MotionImage`, or `Motion` handle registration.

Because both `MotionContainer` instances receive the same controller, each one registers its animation during the effect phase. **Every command is then broadcast to both registered handles without requiring a React render for each playback frame.**

The `stopAnimation: true` initializer makes the preview useful on first paint: newly registered animations receive the stored `finish` command and settle at their final styles. Pressing **Replay** replaces that stored command with `play` and starts the group again.

## Direct controllers are command-driven

Passing the controller object directly switches that Motion Provider component to imperative mode:

```tsx
<MotionContainer
  animation={{ mode: "fadeUp" }}
  controller={controller}
>
  Command-driven content
</MotionContainer>
```

In this form, the component does **not** also run its default in-view observer. Playback waits for controller commands.

If you want a declarative driver first and imperative control later, pass the controller through the `controls` field instead:

```tsx
<MotionContainer
  animation={{ mode: "fadeUp" }}
  controller={{
    configView: { amount: 0.3, once: false },
    controls: controller,
  }}
>
  In-view until a controller command takes ownership
</MotionContainer>
```

The declarative driver remains active while `controller.getSnapshot()` is `undefined`. After the first controller command, the command store owns playback and the in-view driver stops issuing competing commands.

<Callout type="tip" title="Prefer declarative control when events are not involved">
  For a simple viewport reveal, scroll-linked animation, or boolean trigger, pass a declarative `controller={{ ... }}` object directly to the motion component. Use `useController()` when application code genuinely needs imperative commands or one command should coordinate several animations.
</Callout>

## Edge cases

- **The controller is stable, not reactive state.** Playback commands mutate the controller store directly. Reading `controller.size` in JSX does not by itself subscribe the component to registration changes.
- **Unmounted components unregister automatically.** Motion Provider removes their animation handles during effect cleanup, so later commands only target mounted registrations.
- **Initial commands survive registration timing.** Calling `play()`, `reverse()`, or `finish()` before a child animation registers is intentional; the latest command is applied when that handle registers.
- **Reversal is group-aware.** `reverse()` calculates a shared starting time from the registered group so shorter completed effects do not jump ahead of longer ones.
- **Finite numeric validation is strict.** `seek()` and `setPlaybackRate()` reject `NaN` and infinite values.
