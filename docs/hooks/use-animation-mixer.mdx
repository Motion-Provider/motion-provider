**Use `useAnimationMixer()` when several custom `AnimationModule` objects should animate the same element as one definition.** The hook merges their `initial` and `animate` states, memoizes the result, and optionally swaps the final merged endpoints.

It is designed for direct definitions passed to [`Motion`](/components/motion/). If you already use [`MotionContainer`](/components/motion-container/) with named presets, pass an array to `animation.mode` instead of converting those preset names through this hook.

## Signature

```tsx
const definition = useAnimationMixer({
  animations,
  reverse,
});
```

| Option | Type | Default | Purpose |
| --- | --- | --- | --- |
| `animations` | `AnimationModule | readonly AnimationModule[]` | required | One custom module or a non-empty array of modules to merge. |
| `reverse` | `boolean` | `false` | Swaps the merged `initial` and `animate` objects. |

The return value is one `AnimationModule`:

```tsx
{
  initial: MotionState;
  animate: MotionState;
}
```

The hook does **not** add timing, playback state, or a controller. Supply timing through `Motion`'s `timing` prop and choose playback separately through its `controller` prop.

<Callout type="note" title="This hook combines definitions, not timing">
  `duration`, `delay`, easing, iterations, and playback direction are not part of `AnimationModule`. `useAnimationMixer()` only combines the CSS-like motion states that describe where an animation starts and ends.
</Callout>

## Merge order

Modules are processed from left to right. Each `initial` state is merged into the final `initial` object, and each `animate` state is merged into the final `animate` object.

```tsx
const first = {
  initial: { opacity: 0.2, y: 12 },
  animate: { opacity: 0.8, y: 0 },
};

const second = {
  initial: { opacity: 0.6, scale: 0.96 },
  animate: { opacity: 1, scale: 1 },
};

const definition = useAnimationMixer({
  animations: [first, second],
});
```

The result is equivalent to:

```tsx
{
  initial: {
    opacity: 0.6,
    y: 12,
    scale: 0.96,
  },
  animate: {
    opacity: 1,
    y: 0,
    scale: 1,
  },
}
```

**Later modules win when the same property appears more than once.** Properties that do not collide are retained.

This happens independently for each endpoint. A property can therefore be overwritten in `initial` without necessarily being overwritten in `animate`, or vice versa.

<Callout type="warning" title="Mixing is shallow">
  Motion states are flat property maps. `useAnimationMixer()` uses property assignment rather than deep merging nested objects. Treat each CSS or transform alias such as `opacity`, `filter`, `x`, `y`, or `scale` as one replaceable property.
</Callout>

## Reverse the merged definition

`reverse: true` runs *after* the modules have been merged:

```tsx
const result = useAnimationMixer({
  animations: modules,
  reverse: true,
});
```

Conceptually, the hook performs:

```tsx
{
  initial: merged.animate,
  animate: merged.initial,
}
```

It does **not**:

- reverse the order of the modules;
- invoke an animation controller's `reverse()` command;
- change WAAPI playback direction;
- mutate the source modules.

This distinction matters when `reverse` is controlled by React state. The hook produces a different definition; `Motion` then owns how that new definition is played.

<Callout type="tip" title="Use a controller when you mean runtime reversal">
  If the element should keep the same definition and reverse its current timeline position, use [`useController()`](/hooks/use-controller/) and call `controller.reverse()`. Use `reverse` here when you specifically want to swap the definition's endpoints.
</Callout>

## Memoization

The merged definition is created inside `useMemo()` with these dependencies:

```tsx
[animations, reverse]
```

For static definitions, declare the modules outside the component:

```tsx
const modules = [fade, lift, scale] as const;

function Example() {
  const definition = useAnimationMixer({ animations: modules });
}
```

That keeps the `animations` reference stable across unrelated renders.

If you construct a new array inline on every render, the hook must merge it again even when the module contents are unchanged.

<Callout type="tip" title="Keep source modules immutable">
  `AnimationModule` is typed as readonly. Treat the modules and their state objects as immutable values. Mutating an existing array or module without changing its reference can leave the memoized result stale.
</Callout>

## Validation and edge cases

`useAnimationMixer()` validates the module collection while rendering.

| Condition | Result |
| --- | --- |
| One valid `AnimationModule` | Returned as a newly merged definition. |
| Multiple valid modules | Merged in array order. |
| Empty array | Throws `MotionError` with code `EMPTY_MODES`. |
| Module missing `initial` or `animate` | Throws `MotionError` with code `INVALID_ANIMATION`. |

Because these validation errors happen while the hook computes its memoized value, they are **render-time errors**. Handle dynamically sourced animation definitions before they reach the hook, or use an error boundary when invalid application data is possible.

The hook accepts custom `AnimationModule` values only. It does not resolve string preset names such as `"fadeUp"`. Named presets belong in `MotionContainer.animation.mode` or can be imported as actual modules from the presets entry point when you need direct definitions.

## When to use it

| Requirement | Prefer |
| --- | --- |
| Combine several custom modules for one `Motion` element | `useAnimationMixer()` |
| Compose named preset strings | `MotionContainer` with an `animation.mode` array |
| Reverse the current running timeline | `useController().reverse()` |
| Swap a definition's start and end states | `useAnimationMixer({ reverse: true })` |
| Reuse one already-combined static module | Define the `AnimationModule` directly; no hook is necessary |

Because `useAnimationMixer()` uses React's `useMemo()`, call it from a Client Component or another client-side hook.
